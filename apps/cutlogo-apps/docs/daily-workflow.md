# 每日 APP 交付与 GitHub 展示

## 一次完整交付

1. 查商店原页面，记录下载区间、具体功能和核查日期。
2. 选择一个小问题，写清本版范围、验收条件和不支持的输入。
3. 使用共同工程基础实现，完成输入边界、异常和数据处理检查。
4. 构建可安装 APK，模拟器或真机检查主要路径；不能把编译成功写成真机验证。
5. 输出源代码、使用说明、截图、隐私说明、变更记录、测试证据与 APK 校验值。
6. 配套一条 X 草稿：用户问题、应用演示、免费使用方式、源码链接；链接存在后再填写。
7. 用户指定 GitHub 目标后创建真实发布；商店发布另记录审核与可用状态。

## GitHub 展示

总仓库 README 展示应用目录、真实截图、安装入口和完成状态。每个应用独立 README 写清构建与测试方式，保留 issue 模板与变更记录。贡献日历来自实际开发；项目质量、可复现构建和持续维护比提交数量更有说服力。

首期采用一个合集仓库中的 apps 子目录。获得持续需求的应用再拆独立仓库，减少日更造成的维护分散。

## 发布节奏

“一天一个”指完成一个可验证的小范围版本，复杂功能跨天推进。GitHub Release 和 Google Play 上架是两个不同事件；商店审核不由本地流水线控制，不能保证每天审核通过。

当前尚未创建自动任务、GitHub 远程或商店发布。先跑通首个应用，确定用户的目标仓库与发布渠道后再接自动化。
